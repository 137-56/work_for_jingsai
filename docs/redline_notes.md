# 红线自查 · 使用规范

> 配套工具：`scripts/redline_check.py`
> 词表：`redline.yaml`（含敏感串本身，已在 `.gitignore` 中）
>
> 本文是**工程规范**，不是说明文。每一条下面都标了"为什么"，都是踩出来的。

---

## 一、自查器扫的是全文，注释也算

**这是本项目踩过三次的坑，写进规范：**

`scripts/redline_check.py` 按后缀取文本文件（`.md/.py/.json/.yaml/.html/.js/...`），
然后**对文件内容做正则匹配**。它没有、也不该有"跳过注释"的能力——
因为正则眼里没有语法结构，`#` 后面的字和代码里的字是一样的字节。

**定式：任何注释、docstring、Markdown 说明里，都不得原样写出被命中的串。**

要说明"为什么排除某个目录"，写**描述性理由**：

```python
# 压缩后的数学库源码里含圆周率常量，从长数字常量里截出的片段
# 会命中「手机号」规则 —— 纯误报，改不得（改了就破坏固定依赖）。
# 本注释刻意不复述那段数字，否则它自己会被命中。
```

而不是把那段数字抄进注释里。

### 三次返工记录

| 次序 | 场景 | 后果 |
|---|---|---|
| 1 | 为说明"为什么排除三方库"，注释里引用了库源码里的长数字常量 | 注释自己命中，自查器报红 |
| 2 | 同上，改完注释后又在 docstring 里第二次引用 | 同一问题再犯一遍 |
| 3 | 在对话里原样写出了被命中的串，协作者抄进代码注释 | 从源头污染 |

第 3 条尤其要注意：**在协作消息里也不要原样写出命中的串**，
接收方不知道这个约定时会直接抄进代码。

## 二、命中之后：先改数据，别先改检查器

放宽检查器是最省事的做法，也是最危险的做法——它同时关掉了真实风险的告警。
按这个顺序决策：

```
命中
 ├─ 是真敏感信息（校名 / 姓名 / 群号 / 邀请码）？
 │    └─ 是 → 改数据脱敏。绝不加排除。
 └─ 否，属误报
      ├─ 能改数据让它不再被命中吗？
      │    └─ 能 → 改数据（首选）
      └─ 不能（第三方依赖、改了破坏固定版本）
           └─ 才加 EXCLUDE_DIRS，且必须写清理由 + 刻意不复述具体串
```

### 改数据的实例

`data/m3_golden.json` 里的文件摘要是一串十六进制，去掉字母后
截出的数字片段命中了「手机号」规则。
**处置：不排除该文件，而是把摘要每 4 位插一个横杠**——
内容没变，可读了，也不再被误判。

### 加排除之后必须做反例验证

**不验证的排除等于关掉了告警。** 步骤：

1. 造一个测试文件，内容含一个真实格式的敏感样本（用**虚构**的，不要用真数据）；
2. 放在**非排除**目录下；
3. 跑自查器，**必须被抓到**；
4. 验证完删掉测试文件。

如果反例没被抓到，说明排除写宽了。

## 三、通用规则的边界（写数据时要避开）

内置四条正则：号码类 / 证件类 / 长数字类 / 邮箱类。
写数据文件时注意：

- **长连续数字会被当证件号或学号命中**——
  数据里的哈希、编号、指纹尽量用横杠 / 下划线分段，既避误报也更好读。
- **带 `@` 带域名的字符串会被当邮箱命中**——
  示例邮箱地址要用占位域名。
- 第三方库源码（三方库、压缩过的 `.min.js`、模型权重）
  天然含大量长数字常量，**一律靠目录排除，不要试图改它们**。

## 四、扫描范围与时机

```bash
# 提交前必跑（默认的 . 会跳过 .venv / ckpt / outputs / vendor / static / libs）
.venv/Scripts/python.exe scripts/redline_check.py .

# 提交包 / 交付目录单独扫（它们不在 .gitignore 里，且是真正要外发的东西）
.venv/Scripts/python.exe scripts/redline_check.py ../文档/ dist/
```

**时机**：每次 commit 前。这是提交纪律的一条，不是可选建议。
退出码 0 才允许提交；有命中必须逐条处理完再跑一遍。

### 为什么提交包要单独扫

仓库里被 `.gitignore` 排除的文件，打包时会被脚本重新收进去。
**"仓库干净"不等于"提交包干净"**——两者都要扫。

## 五、维护词表

`redline.yaml` 只放**本项目专属**的词（校名、教师称谓、内部群号/平台名）。
通用的号码 / 证件 / 邮箱规则已内置在脚本里，**不要在这里重复**。

**新增词表文件必须以 `redline` 开头命名**——
`EXCLUDE_FILE_PREFIX = "redline.yaml"` 是按文件名前缀排除的，
改名或另起名字会让词表自己变成泄露源。
